## 4. `@unsafe` audit — decision: do NOT adopt

The Cyrius guide suggests wrapping unchecked `load*`/`store*` in `@unsafe { }`.
nous is pervasively manual-memory (every struct accessor is `load64`/`store64`),
and `cyrius deny`/`lint` do **not** flag these for nous (0 violations). Wrapping
every accessor would add noise without a checker enforcing or rewarding it.
**Decision:** keep raw accessors; revisit only if a future cyrius `deny` rule
requires `@unsafe`. (Recorded so the absence is deliberate, not an oversight.)

## 5. External research — resolver completeness

nous covers the resolver fundamentals well: SemVer with 8 constraint operators,
Kahn's topological sort, DFS 3-colour cycle detection, conflict detection across
sources, Levenshtein typo suggestions, cross-source dedup. Against world-class
resolvers (PubGrub / modern pip / cargo), the deliberate gap is **backtracking /
SAT-style constraint satisfaction**: nous resolves via first-match strategy
order, not full version-solving with backtracking. That is a documented design
choice for AGNOS's curated package set, not a defect — flagged in `roadmap.md`
as a possible future direction, not arc-blocking.
